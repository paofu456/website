# 客户资料收集与校验规范（Onboarding SOP）

版本 v1.1 · 2026-09-17
适用范围：从「客户交付资料」到「可以执行 `npm run create-site`」之间的全部工作。

---

## 0. 设计原则

1. **先收资料、再消化、后提问。** 对话中没有资料时，先请用户上传现有文件并等待。收到后先消化画册、PDF 和其他附件，只把资料无法回答的内容列成一轮缺口清单，不先发送几十字段的空表。
2. **字段分三类：资料可消化型 / 必须客户填写型 / 客户决策型。** 企业画册能覆盖公司、产品、案例、客户墙，但永远不会有外贸询盘邮箱、WhatsApp、价格口径、目标市场——这些必须在表单里直接要，别指望从资料提取。
3. **缺口有级别，级别定动作。** P0 阻断（不补不开工）；P1 降级（有降级方案，登记待办，不阻断）；P2 跳过（不追问）。
4. **诚实红线。** 资料里没有的，宁可隐藏区块、写「—」、登记 content-gaps，也不编造。个人联系方式（私人微信/私人手机号）不得当作公司外贸联系方式发布。沿用 `docs/content-contract.md`：Do not create facts to fill visual gaps。
5. **机检能做的绝不靠人看；机检测不出的写明 Agent 检查点。** 格式/尺寸/非空走机检；图片语义、联系方式公私、价格诚实由 Agent 消化校验兜底（两类问题都在实战中真实踩过坑）。

---

## 1. 流程总览（状态机）

```
S0 接单建档 ──→ S1 资料消化 ──→ S2 缺口校验 ──→ S3 客户补料 ──→ S4 建站就绪
   登记资料清单      产出事实库+方案     按第 4 节判定     仅 P0 未清时等待   create-site
                                        P0 / P1 / P2      每轮答复版本 +1
```

- **S3 只对 P0 等待**。P1/P2 不阻断，降级方案先生效，补料到达后增量替换。
- 同一客户的缺口清单一轮问完，不分多轮骚扰。

### 工作区约定

用户不需要提供或创建本地资料目录。对话附件使用运行时给出的真实路径；自动化任务可以提供现有资料目录。Agent 如需建立工作区，必须在模板 catalog 之外进行，站点项目创建后再迁入：

```
<intake 工作区>/<client-slug>/
  ├── materials/           # 原始上传，永不进入静态产物与 git 发布
  └── notes/
      ├── requirements.md    # 已确认事实、站点定位、范围和来源版本
      ├── content-gaps.md    # 信息缺口清单（分级、降级方案、状态）
      └── change-log.md      # 客户确认和重要处理记录
```

`client-slug`：根据确认后的公司身份生成稳定的小写英文或拼音名称，全程使用同一 slug。

禁止把客户附件、PDF 页面、OCR 输出、联系表、图片提取结果或 intake notes 写入 catalog 的 `.tmp/`、`materials/`、模板目录或任何其他位置。

## 2. 收集什么：客户表单（三段式）

### 第一段：必填最小集（5 项，缺一则无法开工）

| # | 字段 | 要求 |
|---|---|---|
| 1 | 公司中、英文名称 | 英文名为外贸站必备；没有则标注「待确认译名」 |
| 2 | 一句话主营 | 我们做什么产品/服务、服务谁 |
| 3 | 产品资料 | ≥1 个产品的任何形态资料（画册/表格/文档/图片+文字说明） |
| 4 | 询盘联系方式 | Email 或 WhatsApp **至少一个**；必须公司外贸用途，不收个人微信/私人手机 |
| 5 | 目标市场 | 国家/地区 + 语言（决定整站叙事、案例取舍与语言） |

### 第二段：资料上传（有多少给多少，Agent 消化）

产品图片（**相机/手机原片优先**，画册兜底）、公司介绍、资质证书、项目案例、客户名单或 logo、工厂/产线照片、其他 PDF / PPT / Word / Excel。

### 第三段：决策项（Agent 给建议，客户拍板）

| 决策 | 说明 |
|---|---|
| 模板 A/B/C | Agent 按第 5 节给默认建议，客户确认 |
| 主推产品线 | Agent 从资料提出 4+1 结构建议（4 条主打 + 1 条候补） |
| 参考站 1–3 个 | 「您希望像谁」——两轮实战客户都主动给了参考站，风格对标是常态，不如一开始就要 |
| 域名现状 | 已有 / 待注册；sitemap 与 canonical 依赖它。未定时 `siteMode: "local"`，禁止收录 |

## 3. 字段分级总表

获取方式：表单 = 必须客户填写；消化 = Agent 可从资料提取，提取不到才问。

| 字段 | 级别 | 获取方式 | 机检规则（L1） | 消化校验（L2） | 缺失处置 |
|---|---|---|---|---|---|
| 公司名 | P0 | 表单 | 非空 | — | 阻断 |
| 英文名 | P0 | 表单/消化 | — | 与中文名同一主体 | 降级：暂用译名并标「待客户书面确认」 |
| 一句话主营 | P0 | 表单 | 非空 | — | 阻断 |
| 产品资料 | P0 | 上传 | 文件可读、页数/数量>0、纯扫描件标记需 OCR | 能提取 ≥1 个完整产品条目（名称+摘要+图+≥3 条参数或卖点） | 阻断 |
| 产品图 | P0 | 上传/提取 | ≥800px 宽；jpg/png/webp | 语义正确：无二维码、证书截图、水印、无关人物 | 阻断（有 1 张可用即可开工） |
| 询盘 Email 或 WhatsApp | P0 | 表单 | email 正则；号码带国家码 | 公司级而非个人（公共邮箱域可用；13x 私人手机标「不得发布」） | 阻断 |
| 目标市场 | P0 | 表单（决策） | 非空 | — | 阻断 |
| logo 源文件 | P1 | 上传 | svg/ai/eps/pdf，或透明底 png ≥500px | 与品牌名一致 | 降级：首字母标顶替，登记待办 |
| 高清产品/实拍原图 | P1 | 上传 | ≥1600px 宽更佳 | 语义逐张确认 | 降级：画册提取图，标注「印版压缩图，待换原片」 |
| 公司介绍素材 | P1 | 消化 | — | 能写出含「成立/地点/主营/≥1 条信任背书」的一段话 | 降级：About 页简版，只写已确认事实 |
| 资质认证 | P1 | 消化 | — | 证书图与文字可对应 | 降级：隐藏区块 |
| 项目案例 | P1 | 消化 | — | 有名称+地点+≥1 个事实点 | 降级：不建 Projects 栏目 |
| 客户名单/logo | P1 | 消化 | — | 需客户确认**可公开授权** | 降级：隐藏客户墙 |
| 服务政策（OEM/ODM/MOQ/交期/质保/售后） | P1 | 表单 | — | 不可从资料推断，属商务政策 | 降级：不写；严禁编造 |
| 地址 | P1 | 表单/消化 | — | 精确到可公开展示级别 | 降级：仅城市级，隐藏地图 |
| 第二联系方式（Phone/总机） | P1 | 表单 | 国际格式 | 公司级 | 降级：隐藏该字段 |
| 域名 | P1 | 表单（决策） | 域名格式 | — | 降级：`siteMode: "local"`，不输出 canonical/sitemap |
| 价格口径 | P2 | 表单 | — | — | 跳过；补上后可显著增强 SEO/GEO |
| 视频/社媒/团队照/新闻稿 | P2 | 上传 | — | — | 跳过 |
| 多语言需求 | P2 | 表单（决策） | — | — | 跳过；首版单语言 |

## 4. 校验三层

### L1 机检（接单即跑，可脚本化）

- 文件可读性：PDF 可打开、页数、是否纯扫描件（无文本层 → 标记需 OCR/按图片处理）
- 图片：格式、尺寸、大小、数量；低于 800px 宽标记
- 格式：email 正则、号码带国家码、域名格式
- logo：扩展名 ∈ {svg, ai, eps, pdf, png}；png 需透明底且 ≥500px
- 输出机检报告：通过项 + 失败项 + 修复指引（错误信息自带修复方向）

### L2 消化校验（Agent 更新 requirements.md 时自检）

- **产品消化测试**：≥1 个产品能凑齐 {名称，一句话摘要，≥1 张语义正确的图，≥3 条参数或卖点}
- **公司消化测试**：能写出含 {成立时间，地点，主营，≥1 条信任背书} 的一段话
- **联系方式公私检查**：邮箱是否公司域/公共域；电话是私人手机还是公司总机。个人联系方式未经明确授权不得发布。
- **图片语义检查**：逐张确认内容，避免二维码、证书截图、水印或无关人物混入产品图。
- **事实冲突检查**：同一事实多来源口径不一致（成立年份、数字）→ 列入缺口清单问客户，不自选

### L3 客户确认

把 `requirements.md` 中的站点提案（市场/买家/核心叙事/主推产品线 4+1/模板建议/栏目清单）与 `content-gaps.md` 合并为一轮，发客户确认。答复写回 `requirements.md`，在 `change-log.md` 记录版本，并逐条关闭缺口。

## 5. 模板选择规则（A/B/C）

| 客户类型 | 默认建议 |
|---|---|
| 工业设备、零部件、耗材；产品多、参数多 | `forge`（产品目录） |
| 设计驱动、高端品牌、精品路线 | `lumen`（极简画册） |
| B2B 服务、集团公司、多业务线综合企业 | `nexus`（现代商务） |

客户无偏好时按此默认。多业务线制造集团按叙事重点决定：重产品参数选 forge，重企业实力选 nexus。

## 6. 缺口清单格式（content-gaps.md）

```markdown
| # | 字段 | 级别 | 为什么需要 | 不补的降级方案 | 状态 |
|---|---|---|---|---|---|
| 1 | 询盘邮箱 | P0 | 询盘接收与通知 | 无，阻断上线 | open |
| 2 | logo 源文件 | P1 | Header 与 OG 图 | 首字母标顶替 | open |
```

- 状态机：`open → answered → confirmed`（Agent 核实答复可用后关闭）
- 每条缺口必须带降级方案（P0 除外）
- 一轮问完；客户答复后版本号 +1，答复内容并入 `requirements.md`，确认动作写入 `change-log.md`

## 7. S4：与建站流程的接口

P0 全清后：

1. `npm run create-site -- --template <id> --target ../<client-slug>-website`
2. `materials/` 迁入新项目（不进 git 发布、不进静态产物）
3. 将 intake 工作区中的 `requirements.md`、`content-gaps.md`、`change-log.md` 迁入新项目 `notes/`
4. `site.config.ts`：`siteMode: "local"`（域名未定），`contentStatus: "draft"`
5. 后续按 `skills/company-website/references/first-build.md` 执行建站

## 8. 常见资料边界

企业画册通常能够提供公司介绍、产品线、部分参数、资质和案例线索，但不能自动证明公开授权，也通常不能确认目标市场、询盘渠道、商务政策、域名和主推顺序。Agent 必须先提取能够确认的内容，再向用户询问这些资料无法回答的决策项。
