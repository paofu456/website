# First website: canonical workflow

1. Materials first: ask for company/product brochures, PDF/Word/PPT/spreadsheets, logo and product images when none were provided, then wait. Read all relevant supplied materials before asking questions. Keep raw uploads, extraction and notes outside the catalog and public assets. Distinguish source facts, confirmed facts, inferences and conflicts; never claim unread pages were reviewed.
2. Consolidated confirmation: ask only unresolved gaps. Confirm company/product facts, target audience, language, pages, visual direction, contact/inquiry destination and behavior, public-use permission, repository name and delivery scope. Recommend Forge for product/specification catalogs, Lumen for image-led premium brands, Nexus for general B2B businesses. Obtain template choice before cloning/scaffolding. Omit nonessential unavailable content with disclosure. Wait for unresolved essential facts/conflicts or publication permissions. Do not fabricate facts or publish placeholders unless an explicitly labeled prototype was requested.
3. Catalog after confirmation: read the task's config path, SITE_BUILDER_CONFIG, or Lucy's `/data/github/site-builder.json`. Non-secret fields: catalogUrl, catalogRef (approved full SHA), catalogVerification, githubOwner, repositoryVisibility. Defaults: https://github.com/paofu456/website.git, paofu456, public. Require an approved full revision. Clone into an isolated catalog directory and check out that exact SHA; verify clean status and read AGENTS.md and README.md. An explicitly designated clean checkout at the same revision may be reused. Never reset existing edits. For operator-verified exact revisions skip repeated catalog builds; otherwise npm ci --include=optional followed by npm run verify. Use saved gh HTTPS authentication, never embed credentials.
4. Separate project: run `npm run create-site -- --template <forge|lumen|nexus> --target <absolute-project-directory>` outside the catalog. Never copy catalog .git. Initialize `git init -b main`, record template/source SHA and confirmed requirements in ignored notes/requirements.md, install npm ci --include=optional. Origin is intentionally absent until delivery. Do not create a remote repository yet.
5. Implement and accept: read generated AGENTS.md, skills/company-website/SKILL.md and its first-build reference. Replace demo facts/assets with authorized content. Keep raw materials/notes/secrets outside public output and commits. Forms cannot claim success without a real destination. Run proportional checks, one final npm run verify (or verify:delivery for real-domain production delivery), then real desktop browser QA and screenshots. Report unresolved gaps; a successful build is not website publication.
6. GitHub delivery after checks: default complete delivery includes a new public repository under paofu456; local-only requests skip remote writes, and explicit visibility overrides defaults. Confirm chosen owner/name and publishable contents. Verify `gh api user --jq .login`. Create via `gh repo create paofu456/<new-name> --public` (or chosen visibility); name collisions must fail, never silently reuse another repository. API failures are not evidence of absence. Add `https://github.com/paofu456/<new-name>.git` as customer origin. Stage only reviewed intended source, commit and push main; never push customer files into paofu456/website. Credentials remain in gh's existing secure configuration.
7. Verify handoff: inspect GitHub host, owner/name, branch and clean worktree. Run `npm run verify:handoff -- --owner paofu456 --repo <new-name> --host github.com`; remote commit must equal local HEAD. Report repo URL, commit, source SHA, template and actual browser coverage. Pages/hosting/DNS/HTTPS and inquiry services are separate deployment tasks.

Maintain a concise checkpoint at each stage. Existing-site modifications clone the customer repository directly and preserve its history. Never switch accounts/providers or re-ask already confirmed facts. Capability installation is not permission to publish a customer site without a corresponding task.
